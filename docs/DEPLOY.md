# Deploying Trailmark

The backend and its database go on Render, the frontend on Vercel. This needs your own accounts, so it is a checklist and not a script.

## 1. Backend and database on Render

1. Push the repository to GitHub (it already is).
2. In Render choose **New, Blueprint**, pick the repository. Render reads `render.yaml` and creates `trailmark-backend` (Docker) and `trailmark-db` (PostgreSQL).
3. It asks for the values marked `sync: false`:
   - `LLM_API_KEY`: your Gemini key from Google AI Studio.
   - `FRONTEND_ORIGIN`: the exact Vercel address, for example `https://trailmark.vercel.app`, with no trailing slash. You can enter a placeholder now and fix it after step 2.
4. `JWT_SECRET` is generated by Render. `COOKIE_SECURE=true` and `COOKIE_SAMESITE=none` are already set, because the frontend and backend are on different domains.
5. When the deploy is green, open `https://<your-service>.onrender.com/health`. It should answer `{"status": "ok"}`. `https://<your-service>.onrender.com/docs` lists every endpoint.

Free Render services sleep after a while without traffic, so the first request after a pause is slow. Open `/health` a few minutes before a demo.

## 2. Frontend on Vercel

1. In Vercel import the same repository and set the **Root Directory** to `frontend`.
2. Add the environment variable `NEXT_PUBLIC_API_URL` set to the Render address (no trailing slash).
3. Deploy, then copy the Vercel address into `FRONTEND_ORIGIN` on Render and redeploy the backend.

## 3. Check it end to end

1. Open the Vercel address in a normal browser window and pick a role.
2. Sign in works and a refresh keeps you signed in (the login cookie is set).
3. As the lead: connect the files from `data/synthetic/`, run the analysis, check the notice says `ai` or `saved`.
4. As the departing member: answer a question. As the lead: approve. As the incoming member: open the handover and confirm receipt.

## If the login does not stick

Browsers can block cookies set by another domain (strict tracking protection, private windows, Safari). Signs: sign-in returns `200` but the next request is `401`. Fixes, in order:

1. Try a normal Chrome window.
2. Put the frontend and backend under one domain, for example a custom domain with `app.` and `api.` sub-domains, and keep `COOKIE_SAMESITE=none`.
3. Make the browser talk only to the Vercel address and have Vercel forward the API paths to Render with `rewrites` in `frontend/next.config.mjs`. The frontend then has to use an empty `NEXT_PUBLIC_API_URL`, which needs a small change in `frontend/src/services/api.ts` (an empty string currently falls back to `localhost:8000`).
